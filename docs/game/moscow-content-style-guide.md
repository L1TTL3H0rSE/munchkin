# Стиль контента `moscow-core`

Этот документ задаёт авторскую и редакторскую границу оригинального набора
`moscow-core`. Он описывает язык и тон presentation metadata, но не расширяет
исполняемую механику: источником истины для неё остаются typed-поля
`content:card-set-v1`.

## Идентичность и права

- Автор: `L1TTL3H0rSE`.
- Лицензия версии 1: `All-Rights-Reserved`.
- Источник: `original-moscow-core-2026`.
- Все названия, тексты, шутки и будущие изображения создаются для этого
  проекта заново.
- Коммерческие названия карт, переводы их текста, персонажи, цитаты, логотипы,
  шрифты, рамки и узнаваемый trade dress не используются.
- Локальный First Edition index служит только непубликуемой матрицей размера,
  deck, абстрактной роли и `interaction_scope`. Его ordinals, публичные
  названия, locators и synopsis не входят в pack, digest, tests или runtime.

`moscow-core@1` является неизменяемой text-only версией. Иллюстрации не
добавляются в неё задним числом: визуальное издание получает следующую
version и новый digest.

## Термины интерфейса

| Typed-термин | Русский текст карты |
|---|---|
| `door` | Дверь |
| `treasure` | Сокровище |
| `combat` | бой |
| `combat strength` | боевая сила |
| `run away` / `escape` | побег / убежать |
| `item` | предмет |
| `equipped` | экипирован |
| `trait` | карта черты: Класс, Раса или усиление черты |
| `tag` | метка героя или монстра |
| `item.slot` | слот экипировки: головной убор, броня, обувь, одна или две руки |
| `hand_limit` | лимит карт в руке |
| `item.size: big` | крупный предмет |
| `level` | уровень |
| `bad_stuff` | последствие неудачного побега |
| `charity` | сброс излишка в конце хода |
| `class` / `race` | Класс / Раса как названия существующих typed-групп |

В rules text используется повелительное наклонение: «получи», «сбрось»,
«возьми», «замени». Числа пишутся цифрами, модификатор — со знаком:
`+2`, `−1`. Временный эффект всегда привязан к «текущему бою» или «текущей
попытке побега», постоянный прямо назван постоянным.

Presentation text не добавляет скрытых правил. Если фраза не имеет точного
typed-представления, меняется фраза или дизайн карты, но не предполагается
разбор естественного языка.

## Тон и темы

Основной тон — доброжелательный городской абсурд: метро, дворы, районы,
погода, доставка, городские профессии, очереди, ремонт, цифровые сервисы и
бюрократия. Шутка строится на узнаваемой ситуации и неожиданном преувеличении,
а не на подстановке московского существительного в чужой текст.

Не используются:

- реальные люди как мишени насмешки;
- унижение жителей по происхождению, здоровью, доходу или району;
- политическая агитация и актуальные обвинения;
- реальные бренды, слоганы, фирменные персонажи и логотипы;
- шутки, для понимания которых нужно знать исходную коммерческую карту.

## Длина и структура

- Название: обычно 2–6 слов, целевой предел 40 знаков, schema limit 120.
- `rules_text`: 1–3 коротких предложения, сначала основной эффект, затем
  условие или последствие; целевой предел 220 знаков, schema limit 800.
- `flavor_text`: одна самостоятельная фраза, обычно до 100 знаков, schema
  limit 300.
- Одна и та же сущность называется одинаково по всему pack. Flavor text не
  повторяет механику и не маскирует обязательное правило.

Для `other_players` карта содержит законченную формулировку с выбранным
соперником. Текущий профиль исключает такую definition целиком; текст не
заменяется заглушкой и не становится доступным self-эффектом.

## Checklist оригинальности

Перед фиксацией карты:

1. Сформулировать независимую московскую ситуацию без просмотра исходной
   формулировки.
2. Записать gameplay intent только через существующий kind/effect/modifier.
3. Написать название, rules и flavor заново; не делать перевод, пересказ
   предложением-за-предложением или замену существительных с сохранением
   чужой шутки.
4. Проверить, что нет коммерческого имени, персонажа, цитаты, бренда, логотипа,
   визуального описания рамки или ссылки на reference.
5. Сверить rules text с typed mechanics и `interaction_scope`.
6. Проверить русский текст, уникальность ID/name, лимиты длины и отсутствие
   `image`/`alt_text` в v1.
7. Выполнить ручной review всей колоды. Exact/fuzzy scan может найти
   подозрительный участок, но не объявляется доказательством правовой чистоты.

Редакторская проверка 29.07.2026 охватила все 168 определений: поля
представления заполнены кириллицей, имена уникальны, а тексты согласованы с
типизированной механикой и `interaction_scope` карт. Машинная сверка не нашла
точных совпадений с
публичными названиями локального индекса или включений его кратких описаний
механики в текст правил. JSON пакета также не содержит полей локального индекса
или импортов к нему.
